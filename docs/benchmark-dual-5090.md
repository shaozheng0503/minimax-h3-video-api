## 一、工作流参数（全部用例统一）

| 参数 | 值 |
|---|---|
| 主模型 (UNet) | `minimax_h3_fl2va_pruned_int8_convrot.safetensors` |
| 加速 LoRA | `minimax_h3_fl2v_turbo_4step_v1.0_768p_comfyui_bf16.safetensors` |
| LoRA 强度 | 1.0 |
| 采样步数 | 4 步 (turbo 蒸馏) |
| 采样器 | euler |
| 调度器 | simple |
| Sigma Shift | video=12.0, audio=3.0 |
| CLIP | `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors` (type=minimax) |
| 视频 VAE | `minimax_h3_video_vae_fp16.safetensors` |
| 音频 VAE | `minimax_h3_audio_vae_fp32.safetensors` |
| Seed | 20260819 |
| 音频轨 | ✅ 启用 (VAEDecodeAudio) |
| 输出格式 | mp4 / auto codec |

### 工作流链路
```
UNETLoader(fl2va) → LoraLoaderModelOnly(turbo_4step) → MiniMaxH3SigmaShift(12/3)
CLIPLoader(Qwen3VL, minimax) ┐
VAELoader(video_fp16)        ┴→ MiniMaxH3ImageToVideo(prompt, W, H, length)
                                  ↓ [0]=CONDITIONING, [1]=LATENT
RandomNoise(seed) → BasicGuider ← MiniMaxH3ImageToVideo[0]
BasicScheduler(simple, 4步) → SamplerCustomAdvanced ← latent_image
VAEDecode(video) + VAEDecodeAudio(audio) → CreateVideo(24fps) → SaveVideo
```

## 四、关键发现

### 1. 双卡 ≠ 单任务加速

**实测确认：ComfyUI 单个任务仍只跑在单卡上。** 双卡实例的生成耗时与单卡实例在同一量级，没有加速效果。

对比（同提示词"机械臂抓取" 5s 16:9）：

| 实例 | GPU | 480p | 720p | 1080p |
|---|---|---|---|---|
| 单卡实例 | 1×5090 | 38.7s | 75.7s | 225.4s |
| 双卡实例 | 2×5090 | 88.4s→38.1s | 75.4s | 227.4s |

> 480p 首次冷加载偏慢是因为新实例首次模型加载；热启动后与单卡一致。  
> **双卡的价值在并发吞吐（同时跑2个任务），不在单个任务提速。**

### 2. 分辨率对耗时的影响

| 分辨率档位 | 像素数 (16:9) | 相对 480p 倍数 | 耗时倍数 (5s) |
|---|---|---|---|
| 480p (864×480) | 0.41M | 1.0× | 1.0× |
| 720p (1280×720) | 0.92M | 2.2× | 2.0× |
| 1080p (1920×1080) | 2.07M | 5.0× | 6.0× |

- 480p → 720p：像素 ×2.2，耗时 ×2.0（接近线性）
- 720p → 1080p：像素 ×2.3，耗时 ×3.0（**超线性**，VAE tiling / 显存压力导致）

### 3. 时长对耗时的影响

| 时长 | 帧数 | 相对 5s 倍数 | 耗时倍数 (720p) |
|---|---|---|---|
| 5s | 124 | 1.0× | 1.0× |
| 10s | 243 | 2.0× | 2.2× |
| 15s | 362 | 2.9× | 5.0× |

帧数与耗时接近线性增长，但 15s 在 1080p 档出现明显超线性（362帧 × 2.07M = 749M 像素处理量，VAE 解码成为瓶颈）。

### 4. 异常数据说明

| 用例 | 异常 | 原因 |
|---|---|---|
| 480p_5s-1 (88.4s) | 比同组热启动慢 2.3× | 新实例首次提交，模型冷加载到显存 |
| 720p_5s-2 (394.0s) | 比同组 720p_5s-1 (75.4s) 慢 5.2× | 推测实例中途被共绩算力调度/抢占，或 GPU 频率降档 |
| 720p_15s-1 (1.3s) | 几乎瞬间完成 | ComfyUI 输出缓存命中——相同参数已生成过，直接返回缓存结果 |

### 5. 画幅对耗时的影响

同分辨率同时长下，4:3 (面积较小) 比 16:9 快：

| 用例对 | 4:3 尺寸 | 16:9 尺寸 | 4:3 耗时 | 16:9 耗时 |
|---|---|---|---|---|
| 480p 10s | 640×480 (0.31M) | 864×480 (0.41M) | 59.6s | 70.7s |
| 720p 10s | 960×720 (0.69M) | 1280×720 (0.92M) | 131.9s | 203.0s |
| 1080p 10s | 1440×1080 (1.56M) | 1920×1080 (2.07M) | 438.0s | 730.8s |

4:3 比 16:9 快约 15-40%，与像素面积差成正比。

## 五、双卡利用情况

### ComfyUI 多卡节点实测

实例上存在以下多卡节点：
- `SelectModelDevice` — 将 MODEL 路由到指定 GPU
- `SelectCLIPDevice` — 将 CLIP 路由到指定 GPU
- `SelectVAEDevice` — 将 VAE 路由到指定 GPU
- `MultiGPU_WorkUnits` — 多 GPU 工作单元分配

**但这些节点需要手动在工作流中配置，默认不启用。** 本次测试使用标准 turbo 工作流（未加 device 选择节点），所有任务实际跑在 `cuda:0` 上。

### 要实现真正的双卡利用，有两种路径：

1. **双实例 + 负载均衡**（推荐生产用）
   - 起两个 ComfyUI 实例，各绑一张卡
   - 前面挂 nginx/Cloudflare Worker 轮询分发
   - 吞吐量 ×2，单任务速度不变

2. **单实例多卡节点**（实验性）
   - 在工作流中加 SelectModelDevice/SelectCLIPDevice/SelectVAEDevice
   - 将 UNet 放卡0、CLIP+VAE 放卡1
   - 理论上能重叠部分计算，但 ComfyUI 的实现不成熟，收益不确定

## 六、生产化建议

| 场景 | 推荐方案 | 预期效果 |
|---|---|---|
| 单用户快速出片 | 单卡 5090 + 768p turbo | 5s 视频 ~40s 出片 |
| 对外 API 服务 | 双卡 5090 + 双实例负载均衡 | 并发 ×2，单用户速度不变 |
| 1080p 长视频 | 降预期或加超分 | 1080p 15s 需 25min，不适合实时 |
| 成本敏感 | 主推 720p | 性价比最优档位 |

| 档位 | 中位耗时 | 建议定位 |
|---|---|---|

| 720p 10s | 168s | 标准档 |
| 1080p 5s | 228s | 高清档 |
| 1080p 10s | 584s | 高清档（限并发） |
| 1080p 15s | 1472s | 不建议对外（太慢） |
